# 보호 목록 자동 점검

서점 개편 중에 주문·입금 연결이 깨지지 않았는지 기계로 비교한다. 개편 전 운영본(태그 `pre-renewal-2026-11-01`, 커밋 676d93c · 3.0 정가 29,000원 적용 직후)의 값을 `baseline.json`에 저장해 두었다.

```bash
node tools/guard/guard.mjs                               # 운영본 ↔ 기준값
node tools/guard/guard.mjs --base http://localhost:4174  # 작업본 ↔ 기준값
```

통과하면 종료 코드 0, 다른 곳이 있으면 1(어디가 어떻게 다른지 줄마다 출력), 점검 자체가 실패하면 2. **1이나 2면 합치지 않는다.**

## 보는 것

| 항목 | 어떻게 |
|---|---|
| 주소가 열리는지 | `/`, `/books/`, `/apps/`, `/francespoon/` (끝 `/` 있을 때·없을 때) |
| 공유 미리보기·제목 | 페이지마다 title, description, og:·twitter: 태그 |
| 구글폼 주소와 칸 이름 | 주문·출시 알림 폼의 action, method, target iframe, 칸 이름·종류·고를 값·필수 여부 |
| 책 선택값 | `entry.1833963440` 라디오 값 (구글폼 선택지와 한 글자도 달라지면 안 됨) |
| 입금 금액 | 책을 하나씩 골라 화면에 뜨는 금액과 안내 |
| 계좌 상자·복사 버튼 | 계좌번호, 은행·예금주, 복사 버튼을 실제로 눌러 반응 확인 (주문서·완료 화면) |
| 서가 → 주문서 연결 | 서가의 책을 누르면 주문서가 그 책으로 맞춰지는지, 곧 나올 책은 출시 알림이 뜨는지 |
| 바로가기 칸 | `/books/#orderFormSection` 등, 사이트 안 링크가 가리키는 칸까지 |
| 보내려던 내용 | 책마다 손님처럼 채워 제출 → 구글폼에 갈 칸 이름·책 값·이메일 복사 칸, 완료 화면의 책·금액·계좌 |

## 주문은 보내지 않는다

- 크롬을 `--host-resolver-rules=MAP docs.google.com ~NOTFOUND`로 띄워 구글폼 주소를 아예 못 찾게 하고, 브라우저 안에서도 한 번 더 막는다.
- 막히지 않은 요청이 하나라도 보이면 그 자리에서 점검을 멈춘다.
- Vercel 방문자 통계도 막아서 점검이 방문자로 잡히지 않는다.

## 기준값을 바꿀 때

가격·선택지를 **일부러** 바꾼 경우에만, 우댕 승인 뒤 운영본에 반영된 걸 확인하고:

```bash
node tools/guard/guard.mjs --save
```

Node 20 이상과 맥의 Google Chrome이 있으면 된다(다른 경로는 `--chrome <경로>`).
